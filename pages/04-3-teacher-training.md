## 연수 목표

1. 행맨을 '친구를 구조하는' 영단어 구조대로 재구성한 의도를 이해하고, 수업 소재를 긍정적으로 다시 디자인하는 관점을 갖는다.
2. 게임 하나를 6단계 문제 해결 모형(문제 발견 → 구조화 → 설계 → 구현 → 테스트 → 공유)으로 깊이 있게 다루는 8차시 흐름을 직접 체험한다.
3. **함수 없는 코드와 함수 코드를 비교하는 수업**(4차시)을 시연하고 자기 수업에 맞게 설계할 수 있다.
4. 상·중·하 산출물 예시를 공동 채점하며 평가 기준과 피드백 방향을 협의할 수 있다.

## 6시간 실습 과정

| 차수 | 주제 | 내용 |
| --- | --- | --- |
| 1 (1시간) | 문제 발견·구조화 | 게임 플레이, 입력–자료–처리–출력 분석, 추적표 (1·2차시 활동지를 교사가 직접 작성) |
| 2 (1시간) | 컴퓨팅 설계 | 문자열·리스트·딕셔너리 암호판(3차시), 함수 설계표 |
| 3 (1시간) | 함수 비교 수업 | 4차시를 학생 입장에서 체험한 뒤, 교사 입장에서 발문·오개념 토의 |
| 4 (1시간) | 구현 | while play() 완성(5차시), 출동 기록표 2차원 리스트(6차시) |
| 5 (1시간) | 테스트·공유 | 검사 없는 버전 테스트(7차시), 형성평가 풀이(8차시) |
| 6 (1시간) | 평가·적용 | 산출물 예시 공동 채점, 우리 학교 수업 설계 발표 |

## 함수 비교 수업(4차시) 운영 팁

| 장면 | 교사 발문 | 예상 반응과 대응 |
| --- | --- | --- |
| 도입 | "두 코드 중 어느 쪽이 좋은 코드일까? 먼저 손을 들어 보자." | 대부분 '짧은 쪽'(nofunc)을 고름 → 수업 끝에 다시 묻기 |
| 실행 | "두 코드의 화면이 다른 곳을 찾아보자." | 다른 곳이 없음 → "그럼 왜 나눌까?" |
| 탐구 | "nofunc의 [B] 구간은 full의 어느 함수가 되었니?" | 이름·받는 값·돌려주는 값으로 대응 |
| 수정 | "미리보기를 넣으려면 몇 줄을, 몇 곳을 고쳐야 했니?" | 2줄 대 7줄, 1곳 대 2곳 |
| 정리 | "함수로 나누면 항상 좋을까?" | 줄 수 증가, 오가며 읽기 등 한계도 함께 정리 |

## 산출물 공동 채점 협의 질문

1. 같은 예시에 서로 다른 수준을 준 경우, 어떤 근거(기능 수 / 자료구조 활용 / 설명 능력)를 더 크게 보았는가?
2. A-중의 '실패할 때 기록이 안 나옴'은 감점 요소인가, 피드백 요소인가?
3. B-하처럼 교사 도움을 받은 줄과 스스로 쓴 줄을 어떻게 구분해 기록할 것인가?
4. 피드백 '다음 단계'를 코드 한두 줄 수준으로 구체화했는가?

## 중학교 수업에 적용할 때

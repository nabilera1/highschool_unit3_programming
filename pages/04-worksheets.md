## [활동지 3] 3~4차시 – 알고리즘 설계
① 의사코드(또는 순서도)로 게임 한 판의 흐름을 적어 보세요. (예시)

```
비밀단어 ← 단어 목록에서 무작위로 하나,  맞춘글자 ← "",  틀린글자 ← ""
반복:
    그림[틀린글자 수], 틀린 글자, 밑줄 단어를 출력
    글자 ← 올바른 알파벳 한 글자를 입력받기
    만약 글자가 비밀단어 안에 있으면: 맞춘글자에 글자 추가
        만약 비밀단어의 모든 글자가 맞춘글자에 있으면: "승리" 출력 후 반복 종료
    아니면: 틀린글자에 글자 추가
        만약 틀린글자 수 = 6 이면: "실패, 정답은 ○○" 출력 후 반복 종료
다시 할지 묻기 → yes면 처음부터
```

② 함수 설계표

| 함수 이름 | 매개변수 | 반환값 | 하는 일 |
|---|---|---|---|
| 알파벳한글자리턴 | 단어목록(사용한 글자) | 알파벳 한 글자 | 올바른 글자가 입력될 때까지 다시 묻는다 |
| 모두맞췄는지 | 비밀단어, 맞춘단어 | True / False | 비밀 단어의 글자를 모두 맞혔는지 확인한다 |
|   |   |   |   |
|   |   |   |   |

③ 데이터 구조 선택: 리스트(              ), 딕셔너리(              ), 2차원 리스트(              )

## [활동지 4] 7차시 – 테스트 케이스와 개선
| 번호 | 구분 | 입력값 | 예상 결과 | 실제 결과 | 통과 | 수정 내용 |
|---|---|---|---|---|---|---|
| 1 | 정상 | a (단어에 있는 글자) | 해당 자리에 글자 공개, 기회 유지 |   |   |   |
| 2 | 정상 | z (단어에 없는 글자) | 틀린 글자에 추가, 그림 1단계 진행 |   |   |   |
| 3 | 경계 | 마지막 남은 글자 | 단어 완성, 승리 메시지 후 종료 |   |   |   |
| 4 | 경계 | 6번째 틀린 글자 | 그림 완성, 정답 공개 후 종료 |   |   |   |
| 5 | 예외 | A (대문자) | 소문자 a로 바꾸어 판정 |   |   |   |
| 6 | 예외 | 1 / ab / ㄱ / (빈 입력) | “알파벳 한 글자” 다시 입력 요청, 기회 유지 |   |   |   |
| 7 | 예외 | 이미 입력한 글자 | “이미 입력한 글자” 안내, 기회 유지 |   |   |   |

※ 예시는 행맨 게임 기준. 각 모둠은 자기 게임에 맞게 고쳐 쓴다.

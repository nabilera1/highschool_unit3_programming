## 6단계 문제 해결 수업 모형

8차시는 하나의 큰 문제 해결 과정입니다. 차시마다 중심 단계가 있지만, 각 차시 안에서도 '질문 → 설계 → 구현 → 확인'이 작게 반복됩니다. 차시 순서는 교육청 수업 모형 문서(부록 04-8)와 같습니다.

| 단계 | 차시 | 영단어 구조대에서 하는 일 |
| --- | --- | --- |
| 문제 발견 | 1 | 행맨을 '친구를 구조하는 게임'으로 바꾸고, 플레이하며 입력–자료–처리–출력과 종료 조건 찾기 |
| 문제 구조화 | 2 | 게임의 자료(단어장, 암호, 말한 글자, 배터리)를 리스트·문자열로 정리하고 추적표로 따라가기 |
| 컴퓨팅 설계 | 3~4 | 문자열·리스트·딕셔너리로 암호판을 만들고, **함수 없는 코드와 함수 코드를 비교**하며 함수로 설계 |
| 구현 | 5~6 | while 문으로 한 판(play) 완성, 출동 기록표를 2차원 리스트와 중첩 for 문으로 |
| 테스트 및 개선 | 7 | 정상·경계·예외 테스트로 오류를 찾고 입력 검사 개선 |
| 공유·확장 | 8 | 나만의 영단어 구조대 발표, 동료 피드백, 형성평가 |

```text
 문제 발견 → 문제 구조화 → 컴퓨팅 설계 → 구현 → 테스트 및 개선 → 공유·확장
    1            2            3~4         5~6          7             8
```

## 수업 방법 키워드

- **PRIMM**: 예측(Predict) → 실행(Run) → 탐구(Investigate) → 수정(Modify) → 만들기(Make). 매 차시 '실행 예시'와 '실습 활동'이 이 순서를 따릅니다. 4차시 함수 비교 수업이 대표적입니다.
- **짝 프로그래밍**: 한 명은 입력(드라이버), 한 명은 확인(내비게이터). 미션마다 역할을 바꿉니다.
- **추적표**: 자료(변수) 값이 입력마다 어떻게 바뀌는지 표로 따라가며 코드를 읽습니다.
- **비교하며 배우기**: 같은 결과를 내는 두 코드를 나란히 놓고 '무엇이 더 좋은가, 왜'를 근거로 토의합니다.
